# 棋灯 (KITO)

中級者以上に向けたブラウザ将棋コーチの試作。ローカルで動くやねうら王の実解析を使います。

## 起動

Node.js 20.19+ / 22.12+。

```sh
npm ci
npm run build
npm run preview
# 別ターミナルで
npm run dev
```

http://127.0.0.1:5173 を通常のブラウザで開きます。初回の `npm run build` はエンジンを public にコピーします。エンジンには SharedArrayBuffer と COOP/COEP ヘッダーが必要です。Vite開発サーバーと本番Workerの両方に設定があります。本番では静的ファイルをWorkerにまとめ、各応答にCOOP/COEPを付けます。`npm run preview` は配信物を http://127.0.0.1:5174 で確認できます。iframe内で動作しない場合は独立タブで開いてください。

## 機能

- やねうら王 NNUE K-P / SuishoPetite 2021-11との対局（1スレッド、ハッシュ32MB）
- 合法手、成り選択、持ち駒、二歩、打ち歩詰め、王手・詰み
- 4回反復の千日手、連続王手の千日手、投了
- 上位3候補の実評価・深さ・読み筋、盤上で読み筋再生
- 段階的なヒントと盤上の事実に基づく定型解説
- SFEN / USIインポート、USIエクスポート
- 局面と考えをブラウザに保存、復習、ノートJSON出力

## 対話コーチ

各手の「解説」ボタンを押したときに、その手をやねうら王で解析し、局面・実際の指し手・合法な読み筋をサーバー経由で選択したAIサービス（OpenAI / Google / Anthropic）のAPIへ渡します。質問は表示中の局面を共有し、同じ局面での直前の会話も引き継ぎます。解説済みの手はモデル別にブラウザに最大100件キャッシュします。AIコーチ上部の「解説モデル」で接続済みモデルを選べます。切り替えは次の解説・質問から適用し、過去の手は自動再生成しません。別モデルで同じ手を比較する場合は吹き出し内の「選択中のモデルで解説」を押します。「全自動解説」は初期値OFFで、ONにするとその後に指す双方の手を自動解説します。切り替え状態はブラウザに保存されます。起動・棋譜の復元・サンプル開始で過去の手をまとめて生成することはありません。OFFにすると未送信・処理中の自動解説を止め、遅れて届いた自動解説も表示しません。設定は同じブラウザの別タブにも反映します。過去に同じ局面の解説があっても、新しい指し手では自動表示せず「解説」を押して開きます。質問履歴は再読み込みでリセットされます。

各解説の吹き出し直下から予想手順を開始でき、再生／停止・1手戻る・1手進む・先頭へ・対局へ戻るを操作できます。予想手順の再生は実戦棋譜に書き込まれません。

### API設定

ローカルでは `.env.example` を参考に `.env.local` に `OPENAI_API_KEY` を設定して `npm run preview` を起動します。Viteの `/api/coach` は5174番のWorkerにプロキシします。キーに `VITE_` は付けません。キーはブラウザ・ソース配布・Gitに含めません。

ホスティングでは同じ名前をSitesのサーバー環境変数にsecretとして登録し、再デプロイします。ローカルのenvファイルは自動アップロードされません。`GET /api/coach/status` は設定の有無とモデル名だけを返します。既定モデルは `gpt-6-luna`（速度と費用を抑えるため `reasoning.effort: none`）。`COACH_DEFAULT_MODEL` で全サービスの既定モデルを指定できます。既存の `OPENAI_MODEL` も既定モデル指定として利用できます。未接続の既定モデルから別サービスへ自動で切り替えて課金することはありません。

対応モデルとサーバー側の秘密変数：

| サービス | モデル | 必要なsecret |
| --- | --- | --- |
| OpenAI | `gpt-6-luna`, `gpt-5.4-mini` | `OPENAI_API_KEY` |
| Google | `gemini-2.5-flash-lite`, `gemini-3.5-flash-lite` | `GEMINI_API_KEY` |
| Anthropic | `claude-haiku-5-5` | `ANTHROPIC_API_KEY` |

各サービスの契約・残高・アクセス権は別です。キー未登録のモデルは画面で「未接続」と表示し選択できません。APIに任意のモデル名や送信先URLを指定することはできません。追加は `worker/coach-models.js` の許可リストと各サービスの接続処理で行います。モデルの選択はこのブラウザに保存し、切り替え前の処理の返答で選択中モデルの表示を上書きしません。各サービスの入力・出力・未完了応答の扱いをテスト応答で確認しています。Gemini・Haikuの実APIによる品質確認は別途必要です。

実APIは残高不足 `credit_balance_exhausted` が確認されており、実モデルによる解説品質の確認はクレジット追加後に必要です。残高不足では自動解説の連続リトライを停止します。

### 解説UIのデモ

`/?demo=coach` または開始局面の「4手のサンプルで試してみる」で体験できます。元の対局を保持し、保存済み棋譜を書き換えません。各手の「解説」ボタンで必要な手だけ実際のAIに説明を要求できます。開始時のAPI呼び出しはありません。予想手順の初期表示は手書きのサンプルで、解説取得後は実際のエンジンの読み筋を再生できます。

## 現在の境界

- 生成AIはAPIキーと利用可能な残高のある環境で動作します。未設定・エラー時はその状態を表示します。
- 定跡データベースは未接続。定跡から外れた手数の断定には対応していません。
- 入玉宣言、時間切れ、KIF/CSA入出力、クラウド同期は未対応。
- 評価値は先手視点。勝率や段級位ではありません。短時間の順位は変わります。
- 「振り返る」等の手の比較は、その手が実測されたMultiPV候補に含まれた場合に限ります。含まれない手を推定で採点しません。
- 復元時は意図せずAIが指さないよう自由研究モードになります。
- ブラウザ保存が使えない場合はトーストを表示。棋譜・ノートをダウンロードしてください。

## 一般公開と課金に向けて

現状はSitesの所有者限定アクセスを前提にしています。APIキーは運営者がサーバーで管理し、ユーザーへ配布しません。一般公開前にログイン、決済Webhookで更新する契約状態、サーバー側の利用権限判定、ユーザー別の利用枠と同時実行制限を実装してください。決済済み表示だけをクライアントで判定する実装にはしません。現在は決済・会員DB・利用量の永続台帳は未実装です。

UI検証用の `node tests/ui-provider-preview.mjs` はビルド済みWorkerを5175番で起動し、OpenAIへの送信をテスト応答に置き換えます。画面に「UIテスト応答」と明記し、実モデルの成功確認には使用しません。
